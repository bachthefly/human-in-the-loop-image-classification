# Mini Labs - General Guidelines

Every mini lab assignment in DA 351 is different. We'll focus on smaller and more manageable problems that you'll need to be able to solve in order to succeed in later assignments. In each assignment, however, we will follow some basic procedural steps. 

## Step 1: Set Up Your Assignment

Just like with regular lab assignments, I'll post a link to that week's assignment on Github Classroom at the start of the lab session. You'll follow that link to set up a group or individual Github repository (depending on the assignment). There you'll find all of the data and code you need for that week's assignment. If you are reading this `README` file, you have already downloaded the first lab assignment. Nice work! Remember to make the following changes to your Github repository in order to turn in the assignment.

1. Create a new branch called `student` (all lowercase)
2. Make `student` your default branch
3. Upload files and/or commit all changes to the `student` branch

Once you've set up the repo, you can download the files you need. You can do this in one of three ways: 

1. Go the repo online, click the green "Code" button, and choose "Download ZIP"
2. If you have the Github Desktop software, you can clone the entire repo using that software
3. (Recommended) You can use command line git commands to clone the repo. 

__Note:__ Option 3 is the most difficult option at first but will save you the most time in the long run, especially if you are doing other things from the command line like activating a virtual environment and launching your Jupyter Notebook kernel.

## Step 2: Open and Rename the Mini Lab Template

Now you're ready to start working on the lab! This template file will typically have an assignment setup section, and then a series of questions that you will answer using code chunks, markdown, or a combination of the two. You do not need to write an introduction, conclusion, etc. for mini lab assignments. Don't forget to rename `assignment-template.ipynb` to something more descriptive like `lavin-tfidf-mini-submission.ipynb`.

## Step 3: Read Assignment Instructions and Complete Lab Report 

In an effort to keep `README` files relatively general, there will often be an accompanying markdown file with specific assignment instructions. As a rule, I will call that file `assignment-instructions.md`. If there is no `assignment-instructions.md`, the lab submission template should be self-explanatory.

## Step 4: Submit Assignment

When you're finished with your writing and your code, you'll convert your Jupyter Notebook to an HTML file. Your HTML file should include all your required writing, code, and visualizations, neatly formatted. ***Make sure you look over the HTML file before you turn it in.*** A common mistake is to review the Jupyter Notebook file but not the converted HTML. When you do this, you might miss code errors or formatting mistakes. 

When finished with the assignment, submit __the HTML file version__ of your assignment submission on Canvas.

As you work, you are encouraged to commit and push all relevant files to the remote version of your Github repo. The Github version is intended to be a safety measure for grading in case the Canvas submission fails in some way. It will also be used to determine partial credit and recognize student effort for non-working code, etc.
